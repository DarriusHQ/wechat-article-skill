# 配图规范（image-guide）

> 优先级：真实系统截图 > AI 效果图（政企读者对真实截图信任度更高）。两者可混用：头图用 AI 生图，正文用截图。

## 1. 编号与命名

- 配图从 1 连续编号：配图1 = 头图（必配）
- 文件命名：`assets/配图N-台名-内容.png`（如 `配图2-方案设计台-间伐参数硬约束.png`）
- 正文引用：`![一句话图注](assets/配图N-xxx.png)`，图注说清"这张图看什么"

## 2. AI 生图（头图必用，概念图可选）

Prompt 模板（五要素，缺一不可）：

```text
【用途】公众号头图 / 正文示意图
【比例】头图 900×383（公众号首图 2.35:1）；正文示意图 900×500
【风格】扁平科技插画 / 拟真 UI 效果图（二选一，整篇统一）
【配色】跟随账号档案主色（示例：森林绿 + 科技蓝，白色背景留白充足）
【元素与构图】主体是什么、数据流向、人物动作、视线焦点
【硬性要求】画面无文字（AI 生成文字必然乱码）；无真实人像照片
```

示例（实战可用）：

> 扁平科技插画风，横版 900×383。画面主体：一名林业设计人员坐在工位前，电脑屏幕上"生长"出一份完整文档（多页层叠卡片效果）；背景是丘陵林场绿色山场，一条发光数据流从山场流入屏幕。森林绿+科技蓝配色，白底留白充足，干净现代，无文字。

## 3. 真实截图路径（可选，需 playwright-cli）

**前置**：Node.js + `npx playwright install chromium`；被截图系统可访问。

**流程**：

1. 列"画面清单"：要截哪几屏、每屏验证什么正文观点（如"间伐参数硬约束逐项打钩"对应正文合规段）
2. 向产品同事要**演示剧本**：入口 URL、按序操作步骤、注意事项（如演示环境禁止刷新）
3. 用 playwright-cli 逐步执行：每步 `waitForTimeout` 等渲染 → `snapshot()` 确认状态 → 关键画面 `fullPage` 截图
4. 遇到文件选择框：准备假文件喂给选择器（演示环境通常只认选择动作）
5. 遇到手写签名板：用 `mouse.move/down/up` 在画布坐标范围内画笔画，确认按钮激活后再点

**裁剪规则**（Pillow，`scripts/crop_image.py`）：

- 必裁：内部红线编号（R1/R6/R11）、技术术语条（awaitHuman、mocks、Human-in-loop 代码名）、内部验收标准面板、调试信息
- 常裁：左侧导航栏（聚焦主体）、底部大面积空白
- 保留：页面自带的"演示数据（已脱敏）"角标（这是加分项）

**降级**：无浏览器环境或 Demo 不可用 → 全部走 AI 生图 Prompt 留位，正文文字改为与 Prompt 画面呼应。

## 4. 门禁 D：图文对齐核对表

- [ ] 正文每个关键数字，能在对应配图中指出来
- [ ] 配图中出现的数据/功能，正文有交代
- [ ] 截图内无内部术语裸奔（R 编号/代码名/内部验收口径）
- [ ] 配图顺序与正文引用顺序一致，编号连续
- [ ] 演示数据有脱敏标注或文中已说明
