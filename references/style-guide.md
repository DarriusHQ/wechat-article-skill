# 文风规范（style-guide）

> 来源：实战复盘。适用于政企向林草/行业公众号，其他账号在阶段 0 建档时按此框架重新提炼。

## 1. 结构模板（六段式）

```text
① 痛点场景切入   一线人员的真实日常，用具体动作而非抽象概念
② 过去 vs 现在   "过去怎么做（哪里痛）→ 现在怎么做的（流程分步）"
③ 实战案例       真实可公开数据走一遍流程，数字与配图同源
④ 理念/原则收束  提炼 2~4 条产品边界或设计原则（如"数字不算错/设计有依据/签字有主"）
⑤ 延伸价值       从单点能力讲到业务闭环（可选）
⑥ 品牌结语       能力版图延伸（呼应过往文章）+ 公司定位一句 + 账号固定结束语
```

- 每个大节用「一、二、三」编号，节内可用 emoji 小标题（跟随账号既往风格，克制使用）
- 段落短：两三句一段，手机上一屏 2~3 段

## 2. 术语翻译（零术语裸奔）

正文不允许出现只有研发能懂的词。对照示例：

| 技术词 | 业务语言 |
|---|---|
| LLM 抽取 / 大模型解析 | AI 读懂文档 |
| 本体 / 知识图谱 | 行业知识底座 / 业务认知网络（尽量不提） |
| SHACL / 规则推理 / Datalog | 逐条对照规程校验 |
| awaitHuman / human-in-loop | 人工确认环节 |
| 数字孪生 | 虚拟镜像（尽量不提） |
| R1/R6 等红线编号 | 不出现，翻译成"设计原则""边界" |

产品名、标准号（GB/T…）、政策文号（林办发〔2025〕5 号）**保留**——这些是信任要素，不是术语。

## 3. 口语化边界（三条硬规则）

口语化能去掉 AI 味，但必须守住：

1. **脱离上下文可懂**：任何口语表达单独拿出来，读者也能明白（"泡在案头"可以缩写娱乐化成"泡住"不行）
2. **标题自解释**：小节标题、文章标题不依赖正文就能看懂；行业黑话不缩写（"小班"不能写成"班"）
3. **政企语境得体**：不抱怨市场价格、不暗示行业普遍陋习、痛点归因于"产能与质量"而非"人不行"

## 4. 节奏与修辞

- 长短句交错：连续三句等长必须拆一句
- 排比慎用：品牌口号句式可用（如"更快发现 · 更准处置 · 更好留痕"），普通段落避免三连排比
- 破折号每千字 ≤2 处
- 不用"此外/值得注意的是/更有价值的是/不仅…更是…"这类填充与否定式排比开头
- 数字表述：约束类数字必须挂规程出处（"间伐后郁闭度不低于 0.6（《森林抚育规程》"）

## 5. 篇幅与配图配比

- 正文 1500~2500 字（以账号档案为准）
- 配图 3~5 张：头图 1 张必配 + 正文 2~4 张
- 图片出现位置：紧跟其解释文字之后，图注一句话说清"这张图看什么"
